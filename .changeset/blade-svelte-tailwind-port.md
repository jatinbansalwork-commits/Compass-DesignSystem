feat(compass-svelte): Tailwind port of the Svelte components

- **A new implementation.** The components are a Svelte 5 runes library styled with Tailwind utility classes, shipped as source. The app compiles Compass's classes with the UnoCSS preset (`@klearnow/compass-svelte/configs/uno`) and icons with the Vite 8 or webpack plugin (`/configs/vite`, `/configs/webpack`); `blade.css` holds the fonts and Compass's own scales. The previous implementation, the package root export and the `/utils` subpath are removed.
- **Theming is CSS variables:** every colour class reads its token's variable, falling back to Compass's standard theme (React's default); an app's brand sets only what branding changes.
- **Entry points:** `@klearnow/compass-svelte/components` (components, their class resolvers and types, `CompassProvider`, `useComponentDefaults`, `getAdapters`, `createCancel`), `/runes` (the runes an app's own components build on) and `/icons`.
- **UI only, web only.** Headless hosts and flows (a form, an opener for overlays opened from code, navigation, async content) and composed components (an overlay that switches by screen, a searchable list) are the app's; Compass keeps their seams as adapters. `ComponentStyleProps` is an interface an app extends, so its own components take provider defaults.
- **CompassProvider** renders the overlay host (one scrim, the box overlays mount in, a polite live region) after its content. The outermost provider hosts every overlay. An app's back handler asks the open overlays first through `back()`.
- **Adapters** (`adapters` on CompassProvider) are live: an adapter the app swaps reaches mounted components, and `null` unsets an enclosing one for a subtree (`CompassAdaptersOverride`). `track`, `vibrate(kind)` (`press`, `select`, `toggle`, `warning`), `announce`, `locale` (Amount's), `reportError`, `navigate` (every `href` renderer routes plain internal clicks through it), `form` (`FormAdapter`: fields register with it, show its errors, and submit buttons submit it), `presentDropdown` and `readOTP`. `track('field_change')` sends `{ name }` only.
- **Across the boundary go plain functions, promises and data**, so an adapter can cross a bridge to a native host. A withdrawal is `cancelled: Promise<void>` (resolves once, never rejects), not an `AbortSignal`; `createCancel()` makes one. A field's `FieldRecord` carries `element()` and `reveal()`.
- **Toasts:** the app renders `ToastContainer` once inside CompassProvider, as React's; without one, no toast code ships. `showToast(toast, { cancelled })` returns a `Promise<ToastDismissReason>`; an action's `onClick` returning a promise shows it busy; `leading` is an icon or `{ image, alt }`. One queue, the page's: `showToast` and every ToastContainer share it (no per-provider queue).
- **Overlays:** `Modal`, `BottomSheet`, `Drawer`, `Popover` and `Menu`, each its own component over the same runes. Modal, BottomSheet and Drawer open from a bound `isOpen` (closing returns focus to what had it), compose their content from Compass React's parts (`ModalHeader`, `ModalBody`, `ModalFooter`, and the BottomSheet and Drawer ones; `resolveModalHeader()`, … and `useModalHeader()` for your own), and take `classes` (`root`, `panel`) to place or reshape the surface. Every overlay reports `onOpenChange`; all but Menu take `initialFocusRef`. Each overlay panel sets `--overlay-gutter`, which ActionList's `inset="overlay"` reads.
- **One rule for what opens and what it reveals:** `children` is the trigger and `content` what it reveals — Tooltip, Collapsible, Popover, Menu (`content` is raw content in place of `body` and `footer`) and a disclosing CardGroupItem. Modal, BottomSheet and Drawer have no trigger, so `children` is their content. Nothing opens on hover but Tooltip.
- **Class lint:** `@klearnow/compass-svelte/configs/lint` is a `blade` plugin for oxlint (`jsPlugins`) or ESLint: `no-conflicting-classes`, `no-interpolated-classes`, `no-unknown-blade-class`, `prefer-token`, and `no-restyle`, which keeps a Compass component's `class` to placing it (margin, size, flex or grid item, position, `hidden`) or repointing a token, as `styleOverride` did. `lintClasses()` lints a component oxlint doesn't hand to plugins.
- **Card** is composed as Compass React's from `CardHeader`, `CardBody` and `CardFooter`; parts rendered as children don't enter the bundle unless used.
- **Fields:** one field shell for every field. TextInput's `format` is React's `#` mask (`onChange` adds `rawValue`), with `transform` for a parse/format pair. PhoneNumberInput's country list is a dropdown under the field, or the app's own via `adapters.presentDropdown('dial-code', request)` (an `ActionListRequest` of data plus `cancelled`), showing the exported `PhoneCountryList`; `defaultPhoneCountries()` is the list. OTPInput asks `adapters.readOTP({ length, cancelled })` once mounted and enabled, and again when the owner resets `value` to `''`; its `onChange` and `onOTPFilled` report `method` (`typed`, `paste`, `autofill`, `adapter`, `value`).
- **Choices:** ActionList, CardGroup and ChipGroup report `{ name, value }`, with `value` shaped as `bind:value` (an array with `selectionType="multiple"`); an item's `onClick` gets `{ name, value, event }`, as React's. A long list takes its options as data (`items` or `sections`, a `row` snippet, `itemKey`) and `isVirtualized` mounts only the rows in view.
- **Display:** Amount, Switch, Card padding, Carousel (`activeSlide`, `autoPlay`, `showIndicators`, …), Tabs (`activation: 'manual'`), Text's `truncateAfterLines` and the `negative`/`positive` typography colours follow Compass React. Tooltips share a delay group with React's 300 ms delays.
